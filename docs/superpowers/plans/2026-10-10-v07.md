# CloudTune V0.7 实施计划

依据用户贴出的完整 V0.7 方案实施；该方案取代早期“试听即上传”的理解。试听不下载，明确选择后点击一键入库才处理。

1. 测试驱动实现版本分类、解释排序与保守的来源状态；同名不同歌手、繁简字、翻唱和标题音质宣传不能误判。
2. 整合独立入库任务：权限与元数据确认、串行获取、标签封面、自动上传和喜欢核验；保存文件 ID，失败仅重试未完成阶段。
3. 调整发现页结构、前三推荐与更多结果、右侧选定音源、四个导航页、全局底部播放器。保留原登录、库管理、元数据编辑和本地导入能力。
4. 搜索支持已支持的 B站完整链接；其他链接仅在受批准音源域名和格式范围内支持，拒绝任意地址抓取。
5. 任务记录保存在本机。中断任务标记待恢复，重启不自动产生下载或外部写入；用户重试时从已有文件继续。
6. 全套回归、模拟依赖和虚拟账号端到端验收、桌面与窄屏视觉检查，重建单一启动入口 V0.7 便携包并排除私人数据。

边界：不实现 V0.9 音频指纹、频谱音质评分、远程服务或 Mac 包；不把 B站标题或转换组件状态标为真实音频质量。测试不访问真实账号上传接口。

## 完成与验收（2026-10-10）

已实现以上 V0.7 核心流程。公开音频试听通过受批准域名的内存流转发，不落盘；B站使用官方嵌入播放器，默认收起并保留跨页播放。
任务检查账号后在执行上传前再次检查；上传/核验/喜欢使用固定会话。每个本地文件按账号保存云盘结果，返回旧账号时复用已成功上传记录。手动喜欢与上传使用同一个文件互斥保护。
封面失败后可重试本地封面；已经上传且缺封面的旧文件不会自动覆盖，保持部分完成并说明需要手动更新。

- 全套回归：61 项，60 通过，1 项 Windows 环境跳过，无失败。
- 新端到端测试：真实 FFmpeg 转换、MP3 信息/封面、范围试听；模拟 A 上传中切换 B、B 独立上传、切回 A 不重复上传、手动喜欢与其他账号上传互斥。未访问真实账号上传接口。
- 浏览器：桌面与 390px 窄窗口检查；无全页横向溢出，切换任务页保留播放器，试听未创建任务。
- 便携包：中文 BAT、系统路径下启动、内置 SDK/工具、空用户目录、重复启动、两用户隔离、重启保留音乐封面、关闭服务均通过。
- ZIP：仅一个根启动 BAT，不含私人的任务/登录/音乐索引或 data 目录。
